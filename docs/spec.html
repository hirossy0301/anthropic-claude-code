競艇統計予想アプリ

branch: claude/cloud-session-credit-verify-mh18aa · Python 3.11 / SQLite / LightGBM / Streamlit

1概要

ボートレース公式の過去データ（番組表・競走成績）を集計します。そのデータから、各艇の1着確率と3連単120通りの確率を推定するアプリです。

データ元：ボートレース公式 ダウンロードページ

  1. 取得LZH を日付ごとに取得、気温は Open-Meteodownload.py / weather.py
  2. 解析固定長テキストを読むparsers.py
  3. 保存SQLite の3テーブルdb.py
  4. 特徴量前日までの情報のみfeatures.py
  5. 1着確率分類モデル＋正規化model.py
  6. 3連単Plackett-Lucemodel.py
  7. 表示画面・CLIapp.py / cli.py
検証状況：
  • パーサー：実ファイル（2026-09-28）で確認済みです。全864艇で番組表と成績の登録番号が一致し、144レースの3連単が払戻一覧と一致しました。この確認で、3桁のボート番号が直前の値と連結される形式に気づいて修正しています。
  • 気温の取得：Open-Meteo の実際の応答で確認済みです。
  • 24場の水面の分類は未確認です。私の知識で作った表です。

風や進入コースは、直前にならないと分かりません。これらを学習で使うと、朝の予想の時に同じ情報がなく、精度が見かけより落ちます。そのため、2つのモデルに分けています。

画面（Streamlit）

  • 画面上部のメニューで「予想」と「予測の仕組み」（このページの要約）を切り替えます。
  • 日付・場・レースを選ぶと、各艇の1着確率（表と棒グラフ）と3連単の上位が表示されます。
  • 直前の予想では「直前情報を取得」ボタンで、公式の直前情報（風向・風速・波高・スタート展示の進入）を自動で入れられます。気温・水温・展示のSTも表示します。
  • 画面上部で「朝の予想」と「直前の予想」を切り替えます。直前の予想では、風向・風速・波高・進入コースを入力します。確定済みのレースには、実際の値が最初から入っています。
  • レースごとに、水面の種類・締切予定時刻・気温も表示されます。
  • 「2連単・3連単のオッズと期待値」を開いてボタンを押すと、その賭け式のオッズページを1回だけ取得し、組み合わせごとの期待値（Harville で組み立てた確率 × オッズ）を高い順に表示します。2着・3着の確率には偏りがあり、この期待値で儲かるかは未検証です（2026-09-28 下関12Rで 3連単 6-4-1 485.0倍・2連単 6-4 84.4倍が払戻と一致することを確認）。
  • 「単勝オッズと期待値」を開いてボタンを押すと、そのレースの単勝オッズを公式サイトから1回だけ取得し、各艇の期待値（1着確率×オッズ）を表示します。同じレースは60秒以内なら取り直しません。
  • 結果が確定しているレースでは、実際の3連単・払戻金と「予想の何位だったか」も表示されます。
  • スマホで見る場合は streamlit run app.py --server.address 0.0.0.0 で起動します。同じWi‑Fiにつないだスマホのブラウザで http://<PCのIPアドレス>:8501 を開いてください。

場コード（--venue）は公式の番号に従います。例：01 桐生、02 戸田、12 住之江、24 大村。

3データ

公式ファイルは Shift_JIS の固定長テキストで、全角数字と全角空白が混ざっています。そこで行ごとに NFKC 正規化（全角英数字を半角に揃える処理）をかけます。そのうえで、桁位置ではなく正規表現で項目を読み取ります。全角と半角が混ざると桁位置がずれやすいためです。

テーブル元ファイル主な列キー

↑ entries には電話投票の締切予定時刻（deadline）も入ります。気温をその時刻の値で引くために使います。

リーク防止とベイズ平滑化

履歴系の特徴量は、予想する日の前日までのデータだけで計算します。当日以降の結果を混ぜると未来の情報が入り込み、バックテストの成績が実力以上に良く見えてしまうためです。同じ日の先に終わったレースの結果も使いません。朝の時点で1日分を予想する使い方を前提にしているためです。

出走数が少ない選手は率が極端な値になりやすいので、事前の値（prior）を k 件分足して平均をならします。

平滑化した率 = (前日までの合計 + prior × k) ÷ (前日までの件数 + k)

61着確率モデル

各艇について「1着になるか」を二値分類で学習します。その出力 si を、レース内で合計が1になるよう正規化します。

pi = si ÷ (s1 + s2 + … + s6)
モデル役割設定
LightGBM本番用（朝用・直前用の2つ）木 400本、学習率 0.03、葉数 31、葉の最小件数 50、行・列のサンプリング 0.8
ロジスティック回帰比較用標準化したうえで学習。欠損は学習データの中央値で補完
場×枠の1着率ベースライン学習期間の「場ごとの枠別1着率」をそのまま確率にする

学習に使うのは、結果が確定していて、6艇がそろい、1着が1艇だけのレースです。欠場や全艇フライングなどのレースは除きます。

確率の較正（枠ごとの補正）

3年分のバックテストで、1号艇の強い・弱いの差を、モデルが実際より小さく見積もっていることが分かりました（強い1号艇は予測より勝ち、弱い1号艇は予測より負ける）。そこで、レース内で正規化する前に、各艇の値を枠ごとの係数で累乗します。

pi = siα(枠) ÷ Σ sjα(枠)
  • α は枠1〜6に1つずつ、合計6つです。1より大きいと、その枠の強弱の差を広げます。
  • α は学習期間の最後の20%で決め、検証期間は使いません。前の80%で学習したモデルの出力に対して、勝者の対数損失が最小になる値を探します。
  • 3年分で求めた値は、1号艇が約1.47、2〜6号艇が1.06〜1.14でした。
  • 本番の学習では config.CALIBRATE = True で有効にしています。

73連単確率

1着確率から、3連単120通りの確率を Plackett-Luce（Harville）モデルで計算します。これは「1着を決めたら残りの艇の中から次の着を決める」という順番で確率を掛け合わせる方法です。

P(a-b-c) = pa × pb ÷ (1 − pa) × pc ÷ (1 − pa − pb)

120通りの確率を合計すると1になります（テストで確認済み）。

1マークの展開予想（決まり手）

公式データには1マーク通過時の順位が記録されていません。そこで、競走成績の見出し行に記録されている決まり手（逃げ・差し・まくり・まくり差し・抜き・恵まれ）で1マークの展開を表します。逃げ・差し・まくり・まくり差しは1マークで勝負が決まった（勝った艇が1マークで先頭に立った）ことを、抜き・恵まれは1マークの後で先頭が変わったことを表します。実データ60日分（9,404レース）では、逃げ 52%、まくり 15%、差し 13%、まくり差し 12%、抜き 7%、恵まれ 0.8% でした。

P(艇 i が決まり手 k で勝つ) = P(艇 i が1着) × P(決まり手 k ｜ 艇 i が1着)

  • 後ろの確率：勝った艇の行だけで、決まり手を LightGBM の多クラス分類で学習します（木200本、学習率0.03、葉15、葉の最小件数200）。正則化を弱くすると、比較用の「場×コースの割合」より悪くなりました。
  • 特徴量：進入コース、場・水面・風・波、その艇の平均ST・勝率・級別・モーター、1コースの艇の平均ST・勝率・逃げ率、1つ内側と外側の艇の平均ST、内側とのSTの差。選手の過去の決まり手の割合（1コースでの逃げ率、2〜6コースでの差し率・まくり率・まくり差し率、前日まで）。
  • 前後の艇の情報は進入コースで引くので、直前の予想で進入コースを変えると計算し直します。
  • 3年分のバックテスト（2023年10月〜2025年9月で学習、直近1年 54,339 レースで検証、進入は実際の値）：勝った艇が分かっているときの決まり手の対数損失は、比較用（場×コースの割合）0.6131 → モデル 0.5957（差 −0.0174 [−0.0191, −0.0157]）、的中率 76.4% → 77.6%。勝った艇も分からない状態での「レース全体の決まり手」の対数損失は 1.268（全レース同じ割合なら 1.351）。寄与は進入コース 69%、1つ内側の艇の平均ST 12%・勝率 12%。
  • 本番への導入：上の結果を確認して MODEL_VERSION = 3 で導入しました。

8評価方法

時系列分割で評価します。--cutoff より前の期間で学習し、それ以降の期間で検証します。ランダムに分割すると、未来のレースで学習してしまうため使いません。

指標定義良い方向
1着的中率1着確率が最も高い艇が実際に1着だった割合高い
対数損失実際の1着艇に付けた確率 p の −log(p) の平均低い
3連単 上位N点の的中率確率の上位N点の中に、実際の3連単が入っていた割合高い
回収率払戻の合計 ÷（N点 × 100円 × レース数）100% を超えれば収支がプラス

  • 回収率は、四半期ごとに見ても 75〜78% で安定しており、100% には届きません。

単勝の期待値バックテスト

確率が当たっていても、オッズが確率に見合っていなければ儲かりません。そこで、各艇の 期待値 = 1着確率 × 単勝オッズ を計算し、期待値が閾値（0.8〜2.0）以上の艇だけを各100円買った場合の回収率を調べます。

  • オッズ：公式サイトのオッズページの締切時オッズを使います。サイトポリシーが大量のアクセスを禁じているため、検証期間（2025年10月〜）から無作為に選んだ 2,000レースだけを、1本ずつ3秒以上あけて取得します（約7時間、GitHub Actions で2回に分けて実行）。取得済みはキャッシュし、同じレースを2度取りません。
  • 確認：勝った艇の「オッズ×100」が成績ファイルの単勝払戻と一致するかを確かめます（2026-09-28 大村1R：1.9倍 → 190円で一致）。
  • 市場の確率：1/オッズ をレース内で合計1にしたものです。モデルの確率と対数損失を比べます。
  • 組み合わせ：p ∝ モデルa × 市場b の a, b を期間の前半で決め、後半で評価します。a が0に近ければ、モデルにはオッズ以上の情報がほとんどないことになります。
  • 回収率の信頼区間：レースを単位にしたブートストラップ（2,000回）で95%区間を出します。比較のため「全艇を買う」「1番人気を買う」「確率1位を買う」も並べます。

10制約と注意

  • 24場の水面の分類は未確認です。公式サイトの「場の特徴」と照合してください。
  • オッズは単勝だけです。公式サイトの情報は私的使用に限られ、大量のアクセスは禁止されています。そのため、バックテスト用は無作為に選んだ2,000レースだけ、画面ではボタンを押したときに1レース分だけ取得します。取得したオッズを他の人に配ったり転載したりしないでください。
  • Harville モデルには偏りがあります。2着・3着の確率に偏りが出やすいことが知られています。改善するなら、2着・3着を別のモデルで補正する方法があります。
  • 直前情報はボタンで取得できます。直前の予想で「直前情報を取得」を押すと、そのレースの公式の直前情報ページを1回だけ取得し、風向・風速・波高・スタート展示の進入コースを入れます（同じレースは60秒以内なら取り直さない）。風向は矢印の画像で場のコースの向きを基準に描かれているため、方位 = (風の番号 − 向きの番号 + 8) mod 16 で変換しています（2026-09-28 の9場で競走成績の風向と全場一致を確認）。出走表の展示タイムも読み取ります（2026-09-28 下関12Rで競走成績と6艇とも一致）。
  • 展示タイムは直前の予想だけで使います。特徴量は展示タイム・レース内の平均との差（マイナスほど速い）・レース内の順位。展示タイムが入っているときは「直前＋展示」モデル、入っていないときは展示タイムなしの直前モデルを使います（展示タイムありのモデルに空欄を渡すと、学習中ほぼ見ていない状態になり予想が崩れうるため）。画面に使ったモデルを表示します。
  • 学習と予想で、風のデータの出どころが少し違います。学習には競走成績に記録された風（レース時の実測）を使い、予想には直前情報（締切前の値）を使います。
  • 気温は、水面の実測値ではありません。場の近くの気象データの格子の値です。過去分は再解析値、当日分は予報値なので、朝の予想では予報のずれが入ります。水温は含んでいません。
  • Open-Meteo の無料枠は非商用利用が条件です。
  • 当日の予想には、当日分の番組表の取り込みが必要です。毎日の自動化（定期実行）はまだ実装していません。
  • 3年分の取得には、1.5秒間隔で約2,200リクエスト、約1時間かかります。
確率は過去データからの統計的な推定です。的中や利益を保証するものではありません。
